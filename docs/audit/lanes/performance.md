# Performance Audit — CheckRaise

**Lane:** PERF  
**Date:** 2026-07-26  
**Auditor:** Claude Sonnet 4.6 (read-only)  
**Build inspected:** `build/` (committed, not rebuilt)

## Summary

**Verification:** 6 verified · 2 adjusted · 0 struck · 2 unsampled

Mobile Lighthouse score is 63 — a meaningful gap driven by two root causes: a synchronous Google Fonts stylesheet blocking ~790 ms of first paint on mobile, and 139 KB of unused JavaScript in the 1.1 MB main bundle (39% of which is `scenarios.js`, eagerly parsed at startup even on the Sign In and Dashboard screens). The data layer is sound today but has no row-count ceiling: `fetchRemoteUser` selects every session row ever written, unbounded, and rebuilds five derived structures from scratch on every login; this is invisible at current scale but creates a user-visible login stall somewhere between 500 and 2 000 sessions (estimate). The CSS file carries approximately 29 dead selectors from the `LegacyLayout` branch (which webpack correctly eliminates from the JS bundle but whose CSS rules ship in the stylesheet). All render-isolation work on the countdown timer is correctly done — `TimerRing` is fully self-contained; its 1-second `setSeconds` tick does not re-render `App` or `ScenarioCard`. The FLIP animation in `Dashboard` correctly uses `useLayoutEffect` and forces a reflow only at transition start, not per-frame. No `useMemo`/`useCallback` gaps were found that would cause per-render identity churn on the gameplay hot path. CLS is 0 on both desktop and mobile. TBT is 60 ms desktop / 290 ms mobile — acceptable.

## Clean areas inspected

- **TimerRing re-render isolation** (`src/components/ScenarioCard.jsx:50–96`): `TimerRing` owns its own `seconds` state; the 1-second `setInterval` tick calls `setSeconds` inside the component only. `App.jsx` holds no timer state. The `onTimeout` callback is stashed in a ref (line 53) so the effect has no dependency churn. The timer does **not** re-render `App`, `ScenarioCard`, or `CanvasLayout` on every tick. Correct.
- **FLIP animation correctness** (`src/components/Dashboard.jsx:141–163`): `useLayoutEffect` fires synchronously after DOM paint; it reads `getBoundingClientRect` once per pill after the rating change, not per frame. The forced reflow is intentional and bounded to the post-session transition, not the steady-state dashboard view. The `matchMedia('prefers-reduced-motion')` guard is present and correct.
- **`appendHistory` deduplication** (`src/App.jsx:190–193`): double-fired timeout/decision events are correctly dropped by the length guard, protecting skill accuracy.
- **Session payload columns** (`src/utils/db.js:143`): the sessions select names only needed columns (`hands, correct_count, created_at, coach_read`) rather than `*`. No column-bloat issue.
- **`historyFromSessions` complexity** (`src/utils/spacedrep.js:385–391`): O(n·h) with h=5 — linear in session count, no nested loops or quadratic growth.
- **`directionTallyFromSessions` correctness** (`src/utils/db.js:46–50`): order-independent sum, no sort or quadratic work.
- **CRA build output structure**: content-hashed filenames (`main.81acb197.js`) ensure Vercel's immutable cache headers are applied correctly to JS/CSS assets in production.
- **`LegacyLayout` dead-code elimination**: webpack correctly tree-shakes `LegacyLayout` (including `TableOval`, `TableVisual`, `DecisionPanel`, `StreetBar` in legacy mode) from the production bundle. Verified: zero occurrences of `table-wrap`, `scenario-card-body` in `build/static/js/main.81acb197.js`.
- **Font variant usage**: all four requested Playfair Display variants (`0,700; 0,900; 1,700; 1,900`) have matching `font-weight`/`font-style` declarations in `App.css`. No unused font variants loaded.
- **CLS = 0**: no layout shift on either desktop or mobile — the fixed-height chrome, static card dimensions, and `deal-in` animation (opacity+transform only) do not cause layout shift.
- **`useCountUp` RAF loop** (`src/components/Dashboard.jsx:68–87`): correctly cancels the RAF and timer on cleanup; runs only at session-result mount time, not on steady-state dashboard renders.
- **`Math.max` spread (`bestSessionCorrect`, `db.js:116`)**: flagged as PERF-08 at P3 (theoretical only at current scale).
