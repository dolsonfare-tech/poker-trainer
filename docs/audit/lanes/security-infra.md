# Security & Infrastructure Audit — CheckRaise

## Summary

CheckRaise's security posture is unusually disciplined for a solo-founder React app: the RLS policies in `supabase/schema.sql` are correct on every table, the coach-read endpoint properly requires a bearer token, input clamps are applied inside `buildPrompt` before assembly (so a hostile client cannot smuggle a mega-payload past `max_tokens`), no secrets appear in client code, `.env` is gitignored and no `.env*` files are tracked, no `dangerouslySetInnerHTML` exists anywhere in `src/`, and React auto-escapes every user-controlled string I traced (`displayName`, coach-read text, feedback body). The `scripts/check-invariants.mjs` gate already enforces the biggest structural rules (RLS-on-every-table, secret-name patterns, `.env` tracked, `ignoreDuplicates` on `createRemoteProfile`).

Real findings are mostly around **the trust model for client-computed profile fields under RLS** (a hostile signed-in client can freely rewrite its own `streak`, `rebuys`, `poker_score`, `sessions_completed`, `hands` JSON, and `correct_count` — currently invisible without a leaderboard, but becomes an integrity problem the moment leaderboards or Pro subscription gates ship), a handful of **prompt-injection surfaces the 200-char clamp does not close**, a **missing CI `permissions:` stanza**, an **open-redirect-adjacent `emailRedirectTo: window.location.origin` on the magic-link flow**, and a small pile of **transitive dev-dep CVEs** (all in `react-scripts` / `webpack-dev-server`, none reachable in prod, still worth a fix pass before the Pro/payments work forces a real dependency review). One P1 correctness bug: `assembleUser` reads `profile.rebuys ?? 0`, so any older cached row that lacks the column reads as zero, but `saveRemoteUser` then writes zero back — a Rebuys clobber vector on legacy rows if any exist.

**Verification:** 8 verified · 2 adjusted · 0 struck · 2 unsampled

## Clean areas inspected

- **No `dangerouslySetInnerHTML` anywhere in `src/`** (grep returned zero matches). Every user-controlled string (`displayName`, `initials`, coach-read `headline`/`evidence[]`/`watchFor`, feedback text, notebook history) is rendered as a React text child, which auto-escapes.
- **Secrets discipline is clean** end-to-end: `api/coach-read.js:24,31,32` reads `CLAUDE_API_KEY` / `SUPABASE_SECRET_KEY` / `SUPABASE_URL` server-only; `check-invariants.mjs:60-68` mechanically blocks any client file from referencing those names or the `REACT_APP_*SECRET*` pattern. `.gitignore:19-23` covers every `.env*` variant. `git ls-files` returned no `.env` matches.
- **`api/coach-read.js` auth path is correct**: 401 without a bearer token (`:35`), 401 on invalid token (`:40-42`), 429 on daily cap (`:49-51`), input shape validated before Anthropic call (`:20-22`), `max_tokens: 500` caps blast radius. Uses service-role client with `autoRefreshToken:false, persistSession:false`.
- **`buildPrompt` clamps ARE applied before assembly** (`api/coach-read.js:114-125` all wrap in `clamp()`), so SEC-4 is a content-injection concern, not a max-tokens abuse one.
- **RLS on every table** with `own-row` policies verified against `supabase/schema.sql:57-77, 91-92, 114-116`. `sessions` is deliberately append-only (no UPDATE/DELETE policy at `:73`). The `enforce_username_change_limit` trigger (`:130-150`) correctly overwrites the client-sent `username_changed_at` so the cooldown clock cannot be reset from the client.
- **Single-file ownership** for supabase (`src/utils/supabase.js` only), db reads/writes (`src/utils/db.js` only), PostHog (`src/utils/analytics.js` only), Sentry (`src/utils/sentry.js` only), AdSense (`src/utils/ads.js` + `AdSlot.jsx`), Claude API (`api/coach-read.js` only) — all mechanically enforced by `check-invariants.mjs`.
- **Sign-out cleanup is thorough**: `App.jsx:132` clears owner-tagged localStorage on `SIGNED_OUT`, `App.jsx:476-486` calls `resetAnalytics()` + `clearSentryUser()` in both sign-out paths.
- **`onAuthStateChange` deadlock rule** (`check-invariants.mjs:75-79`) enforced; `App.jsx:149` correctly defers with `setTimeout(..., 0)`.
- **`createRemoteProfile` no-clobber** (invariant rule 9) verified in place at `db.js:180, 188` (both upserts have `ignoreDuplicates: true`).
- **UsernameEntry client-side validation** (`UsernameEntry.jsx:12-14`) matches the DB `check_length` constraint (`schema.sql:12`); DB check is authoritative.
- **`vercel.json:1-4`** is minimal zero-config — no legacy `builds`/`routes` (fixed July 2026), no exposed rewrites that could leak secrets.
- **`ci.yml` steps** run all gates (invariants, both audits, jest, simulate:schemas, playtest:personas, build, e2e) — the "proactive bug net" claim in CLAUDE.md is real.
- **`.env` contents** (`.env:6-20`) contain only the publishable Supabase anon key, the PostHog phc_ key, and a boolean flag — all documented public by design; no secrets checked in.
- **Sentry PII discipline**: `sentry.js:15` sets `sendDefaultPii: false`; `App.jsx:138, 477, 486` sets/clears only the `id`, never email/name.
- **No `eval`, no `innerHTML`, no `document.write`** anywhere in `src/` (grep returned zero).
- **Coach-read response handling** (`claude.js:44-73`) treats every non-200 as failure with tracked reason; no `eval`/`Function` of response body; the string is passed straight through `parseCoachRead` (`userStorage.js:514-529`) which uses `JSON.parse` in a try/catch and reads only three named string fields.
