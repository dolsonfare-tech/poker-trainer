# Modularity & Code-Quality Audit — CheckRaise

## Summary

**Verification:** 15 verified · 0 adjusted · 0 struck · 1 unsampled

CheckRaise's launch-scope code works and its mechanical gates (invariants, audits, jest, e2e) are impressive, but the client is now carrying three genuine monoliths (`src/utils/userStorage.js` 672 lines, `src/App.jsx` 652, `src/components/Dashboard.jsx` 717) plus a 684-line `ScenarioCard.jsx` where four unrelated child components sit inline. `userStorage.js` in particular has drifted from "localStorage cache + streak math" into an eight-concern grab-bag: cache I/O, cache-owner tagging, difficulty memory, Table Reads storage, direction-of-error classification (schema v2 engine, ~140 lines), balanced/student fallback logic, `deriveSchema` (95 lines), `derivePokerScore`, recent-hands buffer, coach-read wire parser, milestone naming, and the streak state machine — all imported by `App.jsx`, `Dashboard.jsx`, `SessionSummary.jsx`, and `db.js` at once. `App.jsx`'s own file-level comment "Screen routing only" (also in CLAUDE.md) is factually wrong today: the file contains the Supabase auth listener (~70 lines), session orchestration, coach-read persistence, guest flow, streak-delta packing, and the rename cooldown branch. Duplication is real but small: two byte-identical `shuffle()` implementations, two `toLocalDateString()` implementations (the second admits the copy in its comment), two independent `DIFFICULTY_LABELS` maps, two hard-coded copies of the guest gate CTA, and two independent date-formatters in `Dashboard.jsx`. Content pools (`scenarios.js` 7,690 lines / 172 scenarios, `observations.js` 502 / 22) are laid out as one big array each; the batch structure is already commented in-line, so splitting is low-risk. `USE_SINGLE_CANVAS` is a hardcoded `true` — its `LegacyLayout` branch (`ScenarioCard.jsx:326-410, 649-685`) plus the `!USE_SINGLE_CANVAS` block in `App.jsx:629-646` are unreachable. CLAUDE.md still lists `src/utils/gamification.js`, `src/utils/skillrating.js`, `src/components/SkillTracker.jsx`, and `src/data/dummyUser.js` as if reachable; the first three do not exist on disk at all, and `dummyUser.js` (71 lines) is only exported and never imported. `src/hooks/` exists as an empty directory. Prop-drilling is measurable: `onVillainInfo` is 3 levels deep, `onGuestSignIn` is 2 levels but forked across two subtrees, and Dashboard takes 10 named props from App including four callbacks. Nothing here is a launch-blocker, but every monolith listed will fight the next feature (Pro tier, hand-ingestion, meta-read).
