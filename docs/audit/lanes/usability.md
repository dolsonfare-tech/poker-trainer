# Usability Audit — CheckRaise (lane: UX)

**Method.** Drove the real localStorage-mode production build (`build/`, served exactly as `e2e/run.mjs` does, coach endpoint stubbed) with Playwright at desktop 1280×800 and mobile 390×844. Journeys walked live: first-run UsernameEntry → difficulty → full 5-hand session with disagree chips + 👁 table peek → summary → dashboard; chained sessions; dashboard surfaces (ledger, Player Profile, Coach's Notebook, feedback form, account pill); two full Table Reads sessions incl. replay skip, wrong-answer whyNot, and the guide link; VillainGuide all 5 tabs from three entry points; one session + Table Reads under `prefers-reduced-motion`; one hand played keyboard-only. Supabase-gated surfaces (SignIn, guest gates, account menu contents) reviewed statically, labeled `[static review]`. Screenshots in `docs/audit/lanes/ux-shots/`; raw measurement logs in `ux-audit-data.json` / `ux-audit2-notes.json` (ids in the JSON are raw-run ids; this table is authoritative).

**Summary.** The core loop is in strong shape: honest labeling is real in the rendered UI (verified live — "Recommended Play", "Hand Analysis", no "Correct"/"AI" claims), the game is fully keyboard-playable with visible focus, Table Reads is polished on both viewports, and reduced-motion is respected. The two findings that matter are both mobile/trust issues: **on a 390×844 phone the primary actions sit below the fold on both the dashboard and the gameplay screen** (the decision buttons AND the hand-so-far ticker — the context ~20 scenarios grade on — require scrolling at decision time), and **the streak system lies to lapsed users** (a 205-days-stale profile is told "Your 3-day streak is on the line — play one session before midnight" while the stats row shows the dead streak as alive — playing then "resets" it to 1, which will read as betrayal in a product whose brand pillar is honest labeling). The rest is quality debt: a cluster of sub-44px tap targets on secondary-but-frequent controls (the 13px disagree toggle and 27px dispute chips are the playtest-feedback capture mechanism), an unclamped "Play -7 more sessions" countdown, and small a11y polish items.

## Clean areas inspected

- **Keyboard-only play** — full hand playable: 3–5 Tabs into the action buttons (natural order), Enter decides, 4 Tabs → next-btn, Enter advances to the next hand; visible 2px solid focus outline; difficulty confirm and dashboard CTA (5 tabs) both keyboard-reachable.
- **Desktop gameplay geometry** — `.sc2-table` 720×400 (no July-18 collapse class), 54px action buttons with ✕/=/↑ semantic chips, ticker with `$1/$2 CASH · 6-MAX · $200 EFFECTIVE` stakes row, villain bubble present (shots `09`, `50`).
- **Disagree flow + table peek** — all 4 dispute chips render, one-tap submit → "Logged — thanks" state; 👁 peek fades the overlay to opacity 0 revealing the untouched table, "← Back to analysis" restores it (shots `11`, `12`, `55`, `56`) — tap-size issue noted in UX-03 only.
